# Промпты разработки и примеры запросов / Әзірлеу промпттары

Этот документ подготовлен во время текущей доработки Bilim AI. Он содержит инструкции этой доработки в сокращённом изложении и примеры запросов для проверки приложения. **Это не восстановленная история первоначальной разработки**: исходные промпты автора до этой работы не были предоставлены. Примеры ниже не означают, что запрос был отправлен живому сервису или что результат уже проверен.

## Инструкции текущей доработки

Ниже зафиксирован смысл текущих задач; это не дословный журнал чата.

### 1. Сохранить функции и исправить базовый сценарий

> Сохрани все восемь модулей Bilim AI и русско-казахский интерфейс. Сделай полноценное создание карточек и ответов из встроенного демонстрационного банка, Excel и доступной Google Таблицы без Gemini API-ключа. Требуй ключ только при обращении к ИИ. Проверяй обязательные колонки, уровни сложности, пустые данные и достаточность банка. Не заменяй незаметно отсутствующий уровень вопросами другой сложности. Пользователь должен скачать карточки и отдельные ответы.

### 2. Сделать интеграцию с ИИ проверяемой

> Используй пользовательский Gemini API key либо серверный secret DEFAULT_API_KEY. Вынеси идентификатор модели в GEMINI_MODEL, значение по умолчанию — gemini-3.6-flash. Обработай отсутствие ключа, ошибки сервиса и некорректные ответы так, чтобы пользователь мог исправить ввод и повторить действие. Не раскрывай ключ в интерфейсе или ошибках. Проверяй структуру ответа перед созданием документа.

### 3. Уточнить границы демонстрации

> Используй условные обозначения учеников вместо настоящих ФИО. Покажи, что RandomForest обучен на четырёх учебных строках и служит демонстрацией алгоритма: достоверность прогноза не установлена. Не обещай нормативное соответствие планов, конкурсный результат или подтверждённую работу живого API без соответствующей проверки.

### 4. Подготовить документацию и проверку

> Опиши восемь функций, запуск на Python 3.12, зависимости, настройку secrets и pytest. Добавь ручной приёмочный чеклист всех модулей на русском и казахском языках, негативные сценарии и проверку скачиваемых документов. Явно отдели тесты с mocks от проверки настоящего Gemini API. Для заявки сохрани основные промпты и подготовь демонстрацию без персональных данных.

## Как проверять промпты приложения

В задаче по Python выберите «Создать с Gemini» и задайте класс 7, начальный уровень. Пример запроса на русском — «Составь задачу про школьную ярмарку. В первой строке дано число покупок, затем цены. Используй цикл for для подсчёта суммы». Қазақша нұсқасы — «Мектеп жәрмеңкесіндегі сатып алулар туралы есеп құрастыр. Бірінші жолда сатып алулар саны, содан кейін бағалары беріледі. Қосындыны for циклімен есептеу керек». Функция `build_task_prompt` в `python_generator.py` передаёт язык, класс, уровень и запрос. Проверьте вручную сумму на каждом примере и откройте оба TXT. В ученическом файле должно быть условие с примерами, в учительском также должны быть подсказка и решение.

Фактические тексты запросов к модели находятся в `app.py` и функциях `build_ksp_prompt` / `build_ktp_prompt` файла `bilim_core.py`. Интерфейс собирает запрос из выбранного языка и значений полей; приведённые ниже примеры — задания для заполнения этих полей, а не точные копии внутренних запросов. КТП запрашивается по четвертям последовательно, с учётом уже запланированных тем.

Для каждого ИИ-модуля проверьте три вещи: результат относится к введённой теме, использует выбранный язык и не добавляет фактов, которых нет во вводе. Для структурированных результатов дополнительно проверяйте обязательные поля и соответствие документа данным.

## Примеры для русскоязычного сценария

### Карточки через ИИ

- Тема: `Алгоритмы с ветвлением: условие if, 7 класс`.
- Класс: `7`.
- Условные ученики: `Ученик 01`, `Ученик 02`.
- Количество на вариант: один лёгкий, один средний и один сложный вопрос.
- Проверка: вопросы соответствуют теме и уровням; на карточке три задания; отдельный файл содержит ответы именно на эти задания.

### КТП

- Предмет: `Информатика`.
- Класс: `7`.
- Темы: `Понятие алгоритма; линейные алгоритмы; условие if; составление алгоритмов с ветвлением`.
- Учебный год: `2026–2027`; для короткой технической проверки — одна четверть, четыре недели, один час в неделю. Это учебный пример, не школьный календарь.
- Проверка: ровно четыре урока с последовательной нумерацией. Для отдельной проверки нескольких четвертей задайте свои недели и часы и сопоставьте сумму уроков с настройками. Учитель отдельно сверяет цели и содержание с используемой учебной программой.

### КСП

- Педагог: `Демо-педагог`.
- Предмет: `Информатика`; класс: `7`.
- Тема: `Алгоритмы с ветвлением`.
- Цель обучения: `Составлять простой алгоритм с одним условием и объяснять выбор ветви на конкретном примере`.
- Проверка: объяснение, практика и проверка понимания связаны с этой целью; задания выполнимы за время урока. Этот пример не заявляет официальный код цели учебной программы.

### Проверка по фото

Подготовьте свой лист с учебной задачей `12 × 3 = 35`, без ФИО и любых идентификаторов. Сфотографируйте и загрузите его. В поле условия и критериев введите: `Проверь правильность умножения. Объясни ошибку, итоговую отметку не выставляй.`

Проверка: система распознаёт исходную запись, замечает арифметическую ошибку и объясняет правильный ответ `36`. Если изображение нечитабельно, ответ не должен выдумывать его содержимое. Для контрольного сравнения загрузите отдельный пример с правильным решением.

### Характеристика

- Ученик: `Ученик 01`.
- Класс: `8 А`.
- Посещаемость: `90%`.
- Выберите успеваемость и поведение в интерфейсе.
- Дополнительные факты: `Выполняет практические задания, задаёт вопросы при затруднениях, участвовал в учебном групповом проекте`.
- Проверка: текст опирается на эти факты, не добавляет диагнозов, наград или семейных обстоятельств.

### Разминки

- Тема: `Алгоритмы и последовательность действий`.
- Класс: `5`.
- Длительность одной разминки: `5 минут`.
- Проверка: получены три понятных варианта, связанных с темой, каждый рассчитан отдельно на пять минут. Перед уроком выберите один вариант и проверьте его инструкции и ожидаемый результат.

## Сценарии без запросов к ИИ

- **Карточки:** встроенный пример или заполненный Excel; создать карточки и ответы с пустым API-ключом. Это полноценная функция приложения, а не имитация ответа ИИ.
- **EDA:** Excel с колонками `Ученик` и `Балл`; значения `Ученик 01…04` и `60, 70, 80, 90`. Проверить среднее `75` и наличие четырёх наблюдений.
- **ML:** задать показатели в интерфейсе и запустить классификацию. Проверить, что результат явно представлен как демонстрация на четырёх учебных примерах, а не как достоверная оценка ученика.
